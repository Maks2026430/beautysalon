# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Beauty salon platform: a Next.js 14 frontend (landing + client dashboard + admin), a FastAPI backend, a Celery worker for SMS reminders, fronted by nginx and backed by PostgreSQL + Redis. The whole stack runs via Docker Compose.

## Commands

The project is run as a containerized stack. Copy `.env.example` to `.env` first.

```bash
docker compose up --build          # build + start the whole stack
docker compose up backend db redis # run only the API + its dependencies
docker compose logs -f backend     # tail a service
docker compose down                # stop (add -v to drop pg/redis volumes)
```

### Database migrations (Alembic, run inside the backend container)

The `backend` service runs `alembic upgrade head` automatically on startup. Manual usage:

```bash
docker compose exec backend alembic upgrade head
docker compose exec backend alembic revision --autogenerate -m "message"
docker compose exec backend alembic downgrade -1
```

Migrations live in `backend/alembic/versions/`. `env.py` injects `DATABASE_URL` from settings and targets `Base.metadata`, so autogenerate sees all models imported in `app/models/__init__.py` — a model is only picked up if it is re-exported there.

### Backend (local, outside Docker)

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload          # API on :8000
celery -A worker.celery_app worker --beat --loglevel=info
```

## Architecture

### Request routing
nginx (`nginx/nginx.conf`) terminates TLS and splits traffic: `/api/` is proxied to the FastAPI backend **with the `/api` prefix stripped** (so backend routes are defined without it), everything else goes to the Next.js frontend. The frontend's `NEXT_PUBLIC_API_URL` therefore points at `…/api`.

### Backend layout (`backend/app/`)
- `core/` — `config.py` (pydantic-settings, single `settings` instance loaded from env), `db.py` (sync SQLAlchemy 2.0 engine, `Base`, `SessionLocal`, `get_db` dependency).
- `models/` — SQLAlchemy 2.0 declarative models (`Mapped[...]` style). All UUID primary keys default to Postgres `gen_random_uuid()` at the DB level (built into PG 13+, no extension needed).
- `schemas/` — Pydantic request/response schemas.
- `services/` — business logic, isolated from routers: `ai_consultant.py` (OpenAI API, gpt-4o-mini), `sms.py` (smsc.ru), `booking.py` (slot computation / create / cancel), `stats.py`, `price_list.py`.
- `api/` — FastAPI routers (see API routes below).

The migration `0001_initial_schema.py` is **hand-written** to match the models, not autogenerated; keep models and migrations in sync when changing the schema.

### API routes
Routes are defined **without** the `/api` prefix (nginx strips it). Routers in `app/api/`:
- `auth.py` (`/auth`): `POST /staff/login`, `GET /staff/me`, `POST /request-otp`, `POST /verify-otp`, `GET /me`, `POST /refresh`, `POST /logout`.
- `bot.py` (`/bot`): `POST /start` (begin session, first question), `POST /answer` (step-by-step; partial answers in Redis `botstate:{sid}`, returns next question), `POST /result` (**SSE** `text/event-stream`: `chunk` events stream the description, final `done` carries the recommendation), `GET /offer/{session_id}` (resume the 48h timer from Redis), `GET /discount/{user_id}` (active offer from `discount_offers`).
- `catalog.py` (no prefix): `GET /services`, `GET /masters` (filter `?specialization=`), `GET /masters/{id}/slots` (`date_from`, `date_to`, `duration_minutes`).
- `appointments.py` (`/appointments`): `GET /my`, `GET /upcoming`, `GET /history`, `GET /availability` (booking flow, by `service_id`), `POST ""`, `DELETE /{id}` (soft cancel, ≥2h before).
- `profile.py` (`/profile`): `GET ""`, `PATCH ""`.
- `dashboard.py` (`/dashboard`): `GET ""`.
- `admin.py` (`/admin`, read = any staff, write = admin): appointments (`GET`, `PATCH /{id}/status`), clients, masters (`GET/POST/PATCH/DELETE`, `PUT /{id}/schedule`), services (`GET/POST/PATCH/DELETE`, `POST /import`), staff (`GET/POST/PATCH/DELETE`), stats (`GET /stats/revenue`, `/stats/funnel`, `/stats/masters-load`).

`DELETE` on a master/service returns 409 when it is still referenced by appointments — deactivate via `is_active` instead. The AI bot only picks `procedure_id`; price + discount come from `price_list.py`, never the model.

Payments are **not** wired up yet: there is a `payments` table + `YOOKASSA_*` settings but no router or service (the `/payments/*` endpoints from the spec are unimplemented).

### Worker (`backend/worker/`)
Celery app (`celery_app.py`) uses Redis as broker + backend. A beat schedule periodically runs `worker.tasks.scan_and_send_reminders`, which sends 24h/2h appointment reminders — gated per user by the `users.notify_24h` / `notify_2h` flags. The worker reuses the backend Docker image.

### Frontend (`frontend/`)
Next.js 14 App Router with route groups: `(landing)` → `/`, `(client)` → `/dashboard/*`, `(admin)` → `/admin/*`. Built as a standalone output (`next.config.js` sets `output: "standalone"`), which the multi-stage Dockerfile depends on. `NEXT_PUBLIC_*` vars are inlined at build time and must be passed as build args.

### Data model
Eight tables: `users` (clients, by phone), `masters` (+ `master_schedules` for weekly hours, `day_of_week` 0=Mon..6=Sun), `services`, `appointments` (links user/master/service, `status` pending by default), `discount_offers` (bot-issued, time-limited), `payments` (YooKassa), `staff` (admin/staff auth by email + password hash). Auth uses JWT (access 15m / refresh 30d) for staff.
